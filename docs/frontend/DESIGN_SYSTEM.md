# ParkFlow design system — Option 4 "Teal & Navy (Modern Enterprise)"

All tokens live in one place: `resources/css/app.css` (`@theme`). Pages use semantic utilities (`bg-canvas`, `text-ink`, `border-line`, `bg-brand-strong`, `chip-*`, `alert-*`), never raw hex values.

## Tokens
| Token | Value | Use |
|---|---|---|
| `navy` / `navy-deep` / `navy-soft` | #0D3448 / #082B3B / #164A63 | Sidebar (`navy-deep`), avatars, step markers |
| `brand` | #14B8A6 | Decorative teal only (logo mark, active sidebar indicator, progress). **Not for text on white** (2.5:1) |
| `brand-strong` / `brand-stronger` | #0F766E / #115E59 | Primary buttons, links, focus ring (5.5:1 on white) |
| `brand-soft` / `brand-faint` | #CCFBF1 / #F0FDFA | Selected rows/cards, hover |
| `canvas` / `surface` | #F5F8FA / #FFFFFF | Page / cards |
| `ink` / `ink-muted` / `ink-faint` | #102A43 / #526477 / #7B8A99 | Text / secondary text / placeholders |
| `line` / `line-strong` | #DCE6EB / #C3D1D9 | Borders / input borders |
| `success`, `warning`, `danger`, `info`, `neutral` (+ `-line`, `-ink`) | see CSS | Status chips and alerts (6.4–7.7:1) |

Measured contrast (WCAG 2.1): ink/canvas 13.7:1, ink-muted/surface 6.1:1, white on brand-strong 5.5:1, white on navy 13.1:1, sidebar text 7.9–8.9:1.
Light content with the navy sidebar is shipped; **dark mode is intentionally not offered** (the brief allows it only if complete).
Fonts: system stack (Segoe UI on Windows) — no web fonts or CDNs, so the UI works offline.

## Components
* **Layout**: `<x-layouts.app>` (navy sidebar with grouped, collapsible menus generated by `App\Support\Frontend\Navigation`; header with breadcrumb, ANPR engine status chip, Sri Lanka clock, notification bell, profile menu, sign out), `<x-layouts.guest>` (auth screens).
* **Blade components**: `x-page-header`, `x-kpi`, `x-state` (status chip), `x-list-states` (loading skeleton / error with retry / empty), `x-pager`, `x-modal` (focus-trapped dialog, Escape closes, bottom sheet on mobile), `x-field` (server-rendered form field) and `x-xfield` (Alpine-bound field with server validation errors), `x-icon` (inline SVG set).
* **Partials**: `_bill` (server bill), `_receipt` (printable receipt), `_occupancy`, `_anpr-capture`, `_anpr-review`, `_payment-fields`, `_session-filters`, `_session-table`, `_anpr-table`.
* **Alpine helpers** (`resources/js`): `api` (same-origin fetch, CSRF from `XSRF-TOKEN`, error normalisation, 401 → sign-in), `uploadWithProgress`, `dataTable` (server filters, pagination, URL sync, stale-response guard), `form`, `crudPage` (list + create/edit modal), confirmation dialog store (with optional typed confirmation or input), toast store (`aria-live`).

## Status vocabulary (one mapping: `resources/js/lib/format.js` → `STATES`)
Backend values stay internal; users see: Parked · **Gate Authorized** · Checked out · **Available / Occupied / Reserved / Out of Service** · Recognised / Low confidence / Unreadable / Engine unavailable / Duplicate reading / Manual entry · **ANPR Review Required** / Verified / Corrected / Rejected · **Payment Pending** / **Settled** / Failed / Refunded · Gate opened / **Gate Failed** / Simulated (no hardware). A text label is always shown, so colour is never the only signal. Check-In / Check-Out are the names of the two gate flows.

## Formatting
* Money: integer minor units from the server → `LKR 1,500.00` (`fmt.money`, integer arithmetic only). Inputs in rupees are converted with `rupeesToMinor` (string based, exact). The browser never computes prices, totals or balances; the only client arithmetic is the cash "change to give" hint, and the server records the actual change.
* Dates: ISO from the server, displayed in **Asia/Colombo** (`02 Nov 2026, 09:15`, 24-hour). Date filters are sent as Colombo calendar days.
* Plates: monospace "plate" style; the server's normalisation is authoritative.

## Accessibility
Skip link; landmarks (`aside` navigation, `header`, `main`); visible focus ring (3 px, AA contrast); all inputs labelled; dialogs trap focus and close with Escape; status changes announced via `aria-live` toasts; tables scroll inside `.table-wrap` (no page-level horizontal scroll at 320 px); reduced-motion respected; 40 px minimum height on standard buttons and inputs (compact table actions are 32 px). A scripted check (labels, accessible names, alt text, headings) passes on all screens tested; a full manual WCAG audit with assistive technology has **not** been done.

## Responsive
Mobile-first: off-canvas sidebar (< 1024 px), stacked forms, sticky review/payment panels on desktop, bottom-sheet dialogs on phones. Verified with no horizontal overflow at 320, 375, 768, 1366 and 1920 px on every page (scripted crawl).

## Printing
`window.print()` with print CSS that hides the shell (`.no-print`, sidebar, header): receipts, internal ticket, reports.
